# Auth Backend Implementation Plan - In-Memory Mock Authentication System (AC1) # 1. Requirements ## Functional Requirements ### User Management ### signup(username, password) - Registers a new user with the following behavior: - Returns a user object on successful registration - Raises ValueError on: - Duplicate username (user already exists) - Empty username (username is empty string) - Empty password (password is empty string) - Username that is only whitespace (username.strip() == '') - Password that is only whitespace (password.strip() == '') ### login(username, password) - Authenticates a user with the following behavior: - Returns the user object on correct credentials - Raises ValueError on: - Unknown username (user does not exist) - Wrong password (password does not match stored hash) - Empty username - Empty password ### Password Security - Passwords MUST be stored as salted hashes using hashlib.pbkdf2_hmac - Passwords MUST NEVER be stored in plaintext - Use cryptographically secure random salt (os.urandom) - Use minimum 16 bytes salt - Use minimum 100,000 iterations for PBKDF2 ### Project Management ### create_project(owner, name) - Creates a new project with the following behavior: - Returns a Project object with unique id, owner, and name - Raises ValueError if: - Owner is not a signed-up user - Name is empty ### Project Isolation - Projects created under one owner must not appear when querying another owner's projects ### reset_store() - Clears all in-memory state for test isolation ### Data Models ### User Object - username (string) - password_hash (bytes) - salt (bytes) ### Project Object - id (UUID string) - owner (username string) - name (string) ## Non-Functional Requirements ### Language - Python 3.8+ ### Dependencies - Standard library only (hashlib, os, uuid, pytest) - No external dependencies ### Environment - In-memory only (no network, filesystem, or database access) - Deterministic behavior for identical inputs ### Code Quality - Module and test file must include docstring noting this is an in-memory mock and not production auth ## Test Requirements ### Test File - tests/test_ac1_auth.py ### Test Coverage - Minimum 10 distinct test functions - Each test function tests exactly one behavior - Tests use pytest fixture or explicit reset_store() calls for isolation - Tests use plain assert statements with pytest.raises(ValueError) for failure cases - Import everything under test from backend.auth_mock - No reimplementation of logic in test file ### Required Test Cases 1. Signup succeeds and returns a user with the correct username 2. Signup with a duplicate username raises ValueError (existing user is untouched) 3. Signup with an empty username raises ValueError 4. Signup with an empty password raises ValueError 5. Signup with a whitespace-only username or password raises ValueError 6. Login with correct credentials returns the matching user 7. Login with a wrong password raises ValueError 8. Login with an unknown username raises ValueError 9. Password is never stored in plaintext (inspect the store directly and assert the raw password string is not present) 10. create_project returns a Project with the correct owner and name 11. create_project under a username that never signed up raises ValueError 12. Two projects created under the same owner are both retrievable and distinct (different ids) 13. A project created under one user is not visible/returned when querying another user's projects 14. Full integration flow: signup -> login -> create_project -> assert project.owner matches the logged-in username ## API Surface ### Module: backend.auth_mock ### Functions ### signup(username: str, password: str) -> dict ### login(username: str, password: str) -> dict ### create_project(owner: str, name: str) -> dict ### reset_store() -> None ### Data Structures ### User: dict with keys: - username: str - password_hash: bytes - salt: bytes ### Project: dict with keys: - id: str (UUID) - owner: str - name: str ### Internal State ### - users: dict mapping username to user dict ### - projects: dict mapping project_id to project dict ### - user_projects: dict mapping username to list of project_ids ### 2.
